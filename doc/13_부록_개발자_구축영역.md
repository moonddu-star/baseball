# 13. 부록 — 개발자 구축 영역 (디자이너는 참고만)

> **적용 우선순위:** [doc/skills](skills/SKILL.md)가 최우선이며, 이 디자인 가이드는 그다음이다. 충돌하면 스킬 규칙을 따른다. 현재 Baseball은 템플릿 이식 전 POC이므로, 아래 PixiBrown 경로·테마·장르별 UI는 해당 환경의 예시다. [현재 적용 범위](design-audit.md)를 먼저 확인한다.

이 문서는 **개발자가 미리 세팅하는 영역**을 압축해 담는다. 디자이너는 이 내용을 직접 만들지 않는다. 다만 "왜 그 노드를/그 값을 건드리면 안 되는지"를 이해하기 위한 참고용이다.

> 디자이너 실작업 규칙은 `01`, `02` 및 `03~12` 를 본다.

---

## 1. 기술 스택 (고정)

| 항목 | 값 |
| --- | --- |
| 렌더러 | PixiJS 8 |
| 프레임워크 | PixiBrown (사내 PixiJS v8) — `pixibrown/` 수정 금지 |
| 언어 | TypeScript (strict + noUnused* 가 lint 역할, `npx tsc --noEmit` 0건) |
| 번들러 | Vite |
| 씬/프리팹 | PixiBrown Prefab / Scene (SceneMaker 편집) |
| 네트워크 | Socket.IO WebSocket, server-authoritative |
| 결과 검증 | Local Mock / Server Adapter |
| 테스트 | vitest (순수 계산 로직만) |

- Node.js 22.x 이상. `@brown/*` 는 사내 Nexus(`.npmrc` + `NEXUS_TOKEN_NPM`).

## 2. 폴더 구조

```text
프로젝트/
├─ index.html → src/main.ts        # 제품 엔트리
├─ preview.html → src/preview.ts    # SceneMaker 프리뷰(도구)
├─ project.config.ts                # gameId, apiUrl, useLocalServer
├─ raw-assets/                      # 원본 에셋(작업 폴더) ← 디자이너 작업
├─ public/assets/                   # build:assets 결과 ← 직접 수정 금지
├─ pixibrown/                       # 프레임워크 소스 ← 수정 금지
└─ src/
   ├─ main.ts  preview.ts
   ├─ common/    # 공통 계층(GameMain, GameModule, SceneManager, Sequence) — 상속만
   ├─ network/   # adapter, socket, types, local_server — 게임과 무관
   ├─ intro/
   └─ game/      # ★ 게임 고유 로직 (여기가 실제 작업 영역)
      ├─ config/ constants/ core/ network/
      ├─ <domain>/ play/ betting/ hud/ menu/ popup/ auto/
      └─ shared/  # palette, typography, layout, ui, timing, money
```

단방향 규칙: `common/` · `network/` · `intro/` 는 `game/` 을 import 하지 않는다.

---

## 3. 부팅 흐름 (요약)

```text
main.ts → initializeFramework(intro) → Intro → 로그인
  → GameModule 이 game 씬 로드 → GameRoot.start()
     loadPalette / loadTypography  ← prefab 디자인 토큰을 먼저 채움
     Serialize 노드 연결 확인 → 게임 컴포넌트 초기화
  → REQ_ALL_STATE → onAllState() 에서 서버 설정 반영 → 스플래시 제거
```

- **start() 시점엔 서버 설정이 없다.** 초기 표시는 폴백, `onAllState` 에서 다시 채운다.
- **색·타이포 토큰 로딩이 컨트롤러 생성보다 먼저** 와야 한다.
- 컴포넌트는 `@RegisterComponent('...')` 의 basename 으로 전역 등록되며 **유일**해야 한다.

## 4. 계층 · 상태 (요약)

```text
UI → GameMain 서브클래스 요청 메서드 → Sequence.sendMessage
  → Adapter → LocalServer / 실서버
응답 → Adapter / Sequence → GameModule → GameMain.onReceiveEvent
  → 클라이언트용 타입 변환 → 보드/HUD/게임 전용 팝업
```

- `GameMain` 서브클래스가 진행을 조율한다. 자식은 initialize(main)으로 연결하고 public 메서드·콜백으로 소통한다. 로그인/AllState 등 시스템 응답은 템플릿 전용 경로를 유지한다.
- 노드·에셋 참조는 `@Serialize`로 prefab에 저장한다. 신규 게임 코드의 이름 조회는 사용하지 않는다.
- 배선 누락은 실제 템플릿 검증 방식으로 드러내고 SceneMaker에서 연결을 복구한다. 임의 빈 UI를 생성해 가리지 않는다.

---

## 5. 서버 연동 · fail-closed (요약)

- 템플릿 Adapter의 시스템 핸들러·envelope 처리·접속 수명주기는 유지한다. 서버 게임 응답은 GameMain에서 클라이언트용 타입으로 변환한다.
- 로컬 서버 구현과 게임 Payload 확장 범위는 skills/local-server.md를 따른다. LocalServer 교체가 필요하면 createLocalServer()만 오버라이드한다.
- 금전 요청 단일 진입점. `round_id` 로 응답 대조.
- 타임아웃·스키마 불일치 → 결과 불명(uncertain) → **동결(freeze)**. 서버가 확실히 거절 → rejected(동결 안 함).
- 자동 재접속 없음. 단절 시 재시작 안내. 복구는 페이지 재시작뿐.
- 설정 계약: 베팅 한도(min/max bet)는 치명(없으면 동결), 고지 필드(rtp 등)는 경고.

## 6. 디자인 토큰 marker (개발자 세팅, 디자이너 값 조정)

| marker 루트 | 읽는 모듈 | 담는 것 |
| --- | --- | --- |
| `PaletteMarkers` | `shared/palette.ts` | 색 토큰(노드 color/tint) |
| `TypeMarkers` | `shared/typography.ts` | 타이포(노드 fontSize·fill) |

- prefab 이 담는 건 색·fontSize·fill 까지. `fontFamily`·`fontWeight`·`letterSpacing`·`lineHeight`·`padding` 은 코드 진입점(`shared/prefab-ui.ts` 의 `styleText`)이 가진다.
- `__probe` 노드로 팔레트 전달 왕복을 검증(부팅 게이트).

---

## 7. 빌드 함정 (개발자 주의, 디자이너 무관)

- `terserOptions.mangle.properties` 켜지 말 것(직렬화가 프로퍼티명 의존). `keep_classnames`/`keep_fnames` 유지.
- `reflect-metadata` 는 `vendor-pixi` 청크에.
- `*.test.ts` 가 `src/**` 안이면 번들에 vitest 가 섞일 수 있음.
- 배포용 `build:assets`, 개발용 `build:assets:dev`.
- prefab 노드 추가/삭제/이동 후 `@Serialize` 배선 재계산 스크립트 재실행.

---

## 8. 코드 규약 (개발자, 디자이너 참고)

- 파일명 kebab-case, 클래스 PascalCase, 상수 UPPER_SNAKE_CASE.
- 인터페이스 `I`, 타입 `T`, Enum `E` 접두사.
- wire DTO 는 snake_case, 내부 모델은 camelCase(어댑터에서 변환).
- 신규 코드에 `any`/`@ts-ignore`/빈 catch/XSS/민감 로그 금지.
- 타이머·리스너·텍스처는 `onDestroy` 에서 정리(취소 가능한 대기 헬퍼 사용).
