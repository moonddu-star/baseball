# 배팅 스윙 조사·개선 기록

## 현재 구현 — 2026-09-16 원근 카메라·25개 코스

문서 우선순위는 사용자 요청에 따라 **doc/skills → 디자인 MD**다. 최신 승인 순서인 **카메라와 크기 맞추기 → 중앙 코스 스윙 완성 → 25개 코스로 확장**을 현재 POC에 적용했다.

### 최신 수정: 안타 종류별 타구 궤적

| 결과 | 타구 표현 | 비행 시간 | 장면 깊이 | 상승 보정 |
|---|---|---:|---:|---:|
| Single | 투수 정면을 피해 좌우로 낮게 빠지는 타구 | 620ms | 26 | 0.08 |
| Double | 높은 좌우 방향으로 즉시 쭉 뻗는 직선 타구 | 420ms | 38 | 0 |
| Triple | Double과 같은 높은 좌우 방향으로 즉시 쭉 뻗는 직선 타구 | 420ms | 52 | 0 |
| Home Run! | 높은 각도로 상승해 화면 상단 밖까지 나가는 타구 | 1150ms | 64 | 0.25 |

- 위 깊이와 상승 보정은 고정 카메라용 연출 값이다. 2·3루타와 홈런은 도착점 자체가 화면 위에 있으므로 작은 상승 보정으로도 높은 궤적을 만든다. 실제 구장 거리나 물리적 발사각 수치가 아니다.
- 1루타는 외야 도착점, 2·3루타와 홈런은 화면 위 도착점을 사용한다. 장타는 비행 끝까지 불투명하게 표시하고 공 전체가 상단 밖으로 나간 뒤 숨긴다. 2·3루타는 이전처럼 420ms 선형 이동을 사용하며, 출발을 늦추는 시간 보정과 추가 상승 곡선을 제거했다. 1루타와 홈런은 기존 시간 보정을 유지한다.
- 좌우 방향은 접촉 시 한 번 결정하고 비행 중 유지한다. Single은 투수 중심에서 화면 너비의 24–36%만큼 좌우로 벗어난 지점으로 향한다. Double과 Triple은 같은 좌우 갭 방향 범위를 사용한다. 공의 반지름과 배트 길이는 유지하며 멀어지는 크기는 동일한 3D 카메라가 계산한다.
- 판정된 single/double/triple/home-run 심볼을 비행에 직접 전달한다. 확률·배당·정산·OUT 연출·300ms 스윙은 유지한다. 정상/빠른 모드 모두 같은 타구 구분을 쓰고 동작 줄이기에서는 비행을 생략한다.
- 아래의 420ms 직선 타구는 이전 공통 연출 기록이다. 현재는 2·3루타에 빠른 직선 비행을 다시 적용했으며, 최신 값은 이 절이 우선한다.
- 회귀 검사: 320/390/540px × 25개 코스 × 4종류에서 접촉 일치, 서로 다른 비행 깊이와 시간, 카메라 범위, 조기 소멸 방지, 홈런 상단 이탈 확인.
- 브라우저 검사: 390px 정상, 320px 빠른, 390px 동작 줄이기에서 네 결과 문구와 비행 프로필, 9.45배 누적, OUT 완료 확인. 1루타와 홈런의 중간 비행 스크린샷도 점검했다.

### 1. 카메라와 크기

- 후속 외형 수정: 검은 손잡이 커버와 감긴 띠를 제거하고, 손잡이·노브·배럴 전체를 동일한 나무 색상과 나뭇결 재질로 통일했다.

- 미터 단위 공간에 배트 길이 약 0.86m, 최대 지름 0.067m, 공 지름 0.073m를 설정했다. 모든 코스에서 모델 배율은 1이다.
- 원근 카메라: 수직 시야각 38°, 높이 1.55m, 접촉 평면 뒤 2.05m, 아래를 향한 각도 약 9.4°. 기존 2D 배경의 수평선과 타격 영역에 맞춘 연출용 근사값이다.
- 540×960 기준 수평선은 약 y249, 중앙 접촉 지점의 공 지름은 약 48px다. 배트는 가까운 전경에서 크게 보이고 화면 밖으로 일부가 잘린다.
- **물리적 길이·두께는 고정**한다. 원근과 회전으로 화면에 보이는 길이는 변한다. 이전의 화면상 크기 고정과 오른쪽 열 15% 확대는 제거했다.
- 공도 같은 카메라로 그린다. DOM 이모지 공과 별도 크기 애니메이션은 사용하지 않는다.

### 2. 중앙 코스 스윙

- 보이지 않는 어깨→팔꿈치→손목 연결로 자세를 계산한다. 위팔 0.34m, 아래팔 0.33m를 유지하며, 손목 목표를 두 관절의 회전으로 맞춘다. 제품 화면에 팔 모델을 추가하지 않았다.
- 손잡이 진입 후 배럴이 따라오고, 접촉을 통과한 뒤 위로 감기는 순서다. 접촉 전후 각속도가 이어진다.
- 공은 끝 단면이 아닌 **굵은 배럴 옆면**에 맞는다. 배럴 반지름과 공 반지름을 포함해 표면 접촉 위치를 계산한다.
- 배트 스윙은 120ms + 180ms, 총 300ms. 배트 잔상·페이드가 없으며 화면 밖에서 시작하고 끝난다.
- 투구·타구와 배트는 같은 재생 시계를 사용한다. 최신 안타별 타구 연출은 아래 표를 따른다. 1루타는 외야에 도달하며 마지막 18% 구간에서 사라지고, 2·3루타와 홈런은 불투명 상태로 화면 상단 밖까지 이동한다.

### 3. 25개 코스 확장

- 각 슬롯의 화면 중심을 같은 접촉 평면의 3D 좌표로 변환한다. 코스별 확대 대신 어깨 높이·배트 기울기·손목 도달 자세를 조절한다.
- 오른쪽처럼 팔이 이미 뻗은 코스는 손의 추가 전진량을 줄여 손잡이가 뜬 막대처럼 보이는 현상을 완화한다. 팔과 배트 길이는 변하지 않는다.
- OUT은 공 아래로 빗나가도록 한다. 정상·짧게 모드 모두 배트 스윙은 300ms이고, 동작 줄이기는 연출을 생략한다.
- 화면 크기가 바뀌면 카메라 비율과 접촉 좌표를 재계산한다. 표시 마스크 하단(세로 75%)으로 조작부를 보호하며, 상단 제한은 제거해 타구가 화면 위로 나가도록 했다.

### 후속 수정: 안타 타구 방향

- 기존 타구의 0.60m 상승 곡선은 원근 투영에서 과장되어 위로 솟았다 되돌아오는 화면 궤적을 만들었다. 안타의 추가 상승 곡선을 제거해 외야로 뻗는 직선 타구로 정리했다.
- 목표점은 투수 머리보다 위의 좌우 외야다. 안타마다 좌우 방향과 벌어지는 각도를 무작위로 정하며, 같은 슬롯을 다시 쳐도 다른 방향으로 날아갈 수 있다. 방향은 타격 시 한 번 정하고 화면 상단 바깥까지 유지한다.
- 타구 도착 깊이를 접촉 평면 앞 24m로 옮겨 투구 시작 깊이 16m보다 멀리 날아가게 했다. 실제 구장 치수를 복원한 것은 아니다.
- 안타 비행을 120ms에서 420ms로 늘렸다. 배트 스윙은 300ms 그대로이고, 배트 종료 후에도 공의 렌더링과 시계가 이어진다. OUT과 동작 줄이기 처리는 유지했다.
- 25개 실제 라운드에서 22개 안타의 비행 방향·420ms 종료·배트 종료 뒤 공 표시를 확인했다. 작은 화면을 포함한 자동 궤적 검사도 추가했다.

### 후속 수정: 화면 상단까지 타구 표시

- 상단 15% 마스크를 제거하고 타구 목표점을 화면 위 1% 바깥으로 연장했다.
- 안타 공의 페이드를 제거했다. 공 전체가 화면 밖으로 나갈 때까지 원래 불투명도를 유지한다.
- 배트 300ms·타구 420ms와 하단 조작부 보호 마스크는 유지한다.

### 후속 수정: 타격마다 무작위 방향

- 안타의 좌우 방향과 각도를 매번 새로 선택한다. 투수 중심에서 화면 폭의 6~34%를 좌우로 벌린 지점을 목표로 한다.
- 연출용 난수만 사용하며 HIT/OUT 판정과 배당에는 영향을 주지 않는다. 상단 밖까지의 비행·페이드 없음·420ms는 유지한다.

### 후속 수정: 실패 타격의 두 가지 연출

- OUT 판정 시 연출만 무작위로 선택한다(빗맞음·헛스윙 각 50%). 판정·배당·정산은 기존 Mines 규칙 그대로다.
- 빗맞음: 공이 배트 윗면에 접촉한다. 약 0.14초 동안 물리적 높이 약 9cm 올라갔다가 아래로 떨어지며, 총 360ms 재생한다. 접촉 순간에는 작은 기존 접촉 효과를 표시한다.
- 헛스윙: 배트는 공 아래를 지나가고, 공은 실제 투구 시작점에서 이어진 방향을 따라 포수 쪽으로 통과한다. 접촉 효과와 위로 튀는 동작은 없다. 통과 연출은 180ms다.
- 실패 동작은 두 종류로 유지하되 화면 문구는 모두 OUT!으로 통일한다. 배트 스윙은 두 경우 모두 300ms다. 실패 공은 마지막 구간에서 페이드한다.
- 25개 코스에서 빗맞음의 표면 접촉·짧은 상승과 하강·팔 도달 범위, 헛스윙의 비접촉·통과 방향을 검사했다. WebGL·소프트웨어의 정상/빠른 재생과 동작 줄이기에서 OUT 종료를 확인했고, HIT·정산도 회귀 검증했다.

### 후속 수정: 목재 배트 외형 개선

- 직선으로 이어 붙였던 배럴·테이퍼·노브 단면을 단조 3차 곡선으로 보간했다. 곡면은 기존 최대 지름 6.7cm와 전체 길이 86.2cm를 넘지 않는다.
- WebGL 모델은 원주 80분할과 세분화한 길이 방향 단면을 사용한다. 끝부분과 손잡이의 각진 연결을 완화했다.
- 전체에 동일한 목재 재질을 유지하고, 길게 이어지는 나뭇결의 굴곡·농도·굵기를 불규칙하게 표현했다. 모델 좌표에 고정해 스윙할 때 결이 미끄러지지 않는다.
- 비금속 물리 재질의 표면 거칠기와 얇은 투명 코팅 반사를 적용했다. 새 이미지나 외부 텍스처 파일은 추가하지 않았다.
- 소프트웨어 렌더러는 가벼운 곡면 모델과 보간된 법선의 음영을 사용한다. 세밀한 나뭇결·코팅 표현은 WebGL에서 제공한다.
- 두 렌더러에서 모델 치수, 셰이더 오류 없음, HIT·정산·빗맞음·헛스윙 재생을 확인했다. 스윙 길이·접촉 위치·공 궤적은 유지했다.

### 후속 수정: 실패 결과를 읽는 시간

- 빗맞음·헛스윙의 공과 배트 연출이 모두 끝나면 화면을 1,200ms 유지한 뒤 라운드 종료 팝업을 표시한다.
- 대기 중에는 OUT! 문구를 페이드 없이 표시하고 입력 잠금을 유지한다. 팝업 전환 후 기존 정리 루틴이 문구를 숨기고 잠금을 해제한다.
- 정상·빠른 모드 모두 같은 인지 시간을 제공한다. 동작 줄이기에서도 움직임 없이 결과 문구를 읽는 시간을 제공한다. 안타의 진행 속도와 정산은 유지한다.

### 후속 수정: 결과 문구와 크기

- 실패 화면의 빗맞음·헛스윙 설명을 제거하고 OUT!으로 통일했다. 실제 두 실패 동작과 팝업 전 1.2초 대기는 유지한다.
- HIT!과 OUT!의 공통 글자 크기를 화면 폭의 7%에서 14%로 두 배 확대했다.

### 후속 수정: 투수 동작 구간 확장

- 기존 스프라이트의 4개 자세를 활용해 준비 → 다리 들기 → 힘 모으기 → 릴리스 → 팔 뻗기 → 후속 동작 → 자세 회복의 7개 재생 구간을 구성했다. 새 포즈 이미지나 모션 캡처를 추가한 것은 아니다.
- 최신 요청으로 일반·빠른 모드 모두 준비부터 릴리스까지 400ms(와인드업 320ms + 릴리스 80ms)로 맞췄다. 단계 사이 프레임 대기가 누적되지 않도록 공통 종료 시각으로 보정하며, 마지막 프레임 단위 오차는 남을 수 있다.
- 발 부근을 축으로 작은 위치·회전 변화를 주고, 원본 자세 전환에는 짧은 혼합 시간을 둔다. 배율을 바꾸거나 투수 크기를 늘리지 않는다.
- 공·배트의 시계는 준비 동작이 끝난 실제 릴리스 시점에 시작한다. 투수의 후속 동작은 투구 비행과 함께 재생하며, 라운드 진행은 후속 동작 종료도 기다린다.
- 연출 정리 시 진행 중인 투수 애니메이션을 취소하고 준비 자세·위치를 복구한다. 동작 줄이기는 투수 애니메이션을 생략한다.
- WebGL·소프트웨어의 정상/빠른 모드에서 7개 단계 순서와 공 출발 시점을 확인했다. 동작 줄이기, HIT·정산, 실패 2종과 OUT 팝업도 확인했다. 기존 배트 300ms, 안타 비행 420ms, OUT 인지 시간 1.2초는 유지한다.

### 검증과 한계

- 자동 검사 10개 통과: 룰·정산·서버 검사 및 320/390/540px·25개 코스·HIT/OUT에서 물리적 길이, 팔 길이, 표면 접촉, 헛스윙 간격, 속도 연속성, 화면 밖 시작/종료를 확인했다.
- 실제 브라우저 25개 라운드에서 HIT 22회·OUT 3회와 정산을 확인했다. 리사이즈 후 접촉 오차 약 0.32px, 그래픽 컨텍스트 중단 시 대기 종료, 페이지 오류 없음.
- WebGL 및 소프트웨어 렌더링에서 HIT·OUT·정산·취소·동작 줄이기를 확인했다. 중앙과 모서리 자세를 이미지로 점검했다.

## 최신 스윙 속도: 0.3초

사용자 요청으로 접촉 전 120ms + 접촉 후 180ms, 총 300ms로 변경했다. 기존 궤적을 1.5배 시간으로 재생하고 접촉 각속도도 같은 비율로 낮췄다. 기본·짧게 모드 모두 적용한다. 배트 크기, 오른쪽 열 15% 확대, 끝 중심 접촉은 유지한다. 투구·타구의 속도는 그대로 두고, 남은 배트 마무리가 끝난 뒤 다음 입력을 받는다. 동작 줄이기는 기존처럼 연출을 생략한다.

## 오른쪽 열 크기 보정

사용자 요청에 따라 **5번째 열만 15% 균일 확대**했다. 배트 끝 중심을 기준으로 손잡이 쪽을 연장하므로 타격 위치와 배트 끝 궤적은 바뀌지 않는다. 1~4번째 열은 기존 크기·자세·궤적을 유지한다. 선택한 코스의 크기는 스윙 내내 일정하며, 다음 코스를 선택할 때 해당 열의 배율로 설정한다. 모든 프레임에서 오른쪽 열의 그립이 화면 밖에 남는지 검증한다.

## 크기 고정·끝 중심 접촉

사용자가 길어지는 현상을 지적하고 **항상 같은 크기, 배트 끝 중심 접촉**을 요청했다. 아래 최초 시안의 옆면 접촉과 가변 깊이 회전은 이 요청으로 대체했다.

- 원인: 이전 검사는 3D 공간의 길이만 확인했다. 깊이 방향 회전 때문에 화면 투영 길이는 달라졌고, 축별 배율도 1.52/1.10으로 서로 달랐다.
- 수정: 모델에 1.10 균일 배율을 적용하고 깊이 각도를 고정했다. 화면 평면의 이동·회전만 애니메이션하며 크기와 두께를 바꾸지 않는다.
- 접촉: 공 중심과 배트 끝 단면의 중심이 일치한다. 코스에 맞춰 배트를 늘리지 않고 전체 위치를 옮긴다. OUT은 공 아래로 빗나간다.
- 검증: 320/390/540px 폭, 25개 코스, 정상·짧게, HIT/OUT 전 프레임에서 손잡이 끝부터 배트 끝까지의 화면 투영 길이를 측정한다. 렌더링 변환 행렬로 두께도 확인한다. 배율 변경과 원근에 의한 길이 변화 모두 회귀 검사 대상이다.
- 같은 화면 폭에서 크기가 일정하다. 화면 크기가 달라질 때만 UI와 같은 비율로 조정한다. 화면 경계에 가려지는 부분과 모델 자체의 크기는 구분한다.
- 0.2초, 잔상·페이드 없음, 기존 게임 규칙 유지. 브라우저 실제 라운드와 7개 자동 검사가 통과했다.

## 최초 시안 기록 — 위 최신 수정이 우선

### 왜 어색했나

기존 코드와 자세 샘플에서 확인한 문제:

- 공의 중심을 배트 끝 단면에 맞춰, 옆면으로 때리기보다 끝으로 찌르는 형태였다.

마지막 문장의 시각적 인상은 구현을 보고 내린 판단이다. 사람의 자연스러움 평가는 자동 검사로 확정할 수 없다.

## 적용 내용

- **배럴 옆면 접촉**: 배트 두께와 공 반지름을 포함해 접촉 위치를 계산한다.
- **화면 밖 그립**: 좌우 코스 때문에 그립이 이동하지 않으며, 높이에 따른 작은 조정만 허용한다.
- **공을 통과하는 회전**: 몸통 방향의 축으로 먼저 휘두른다. 높은 공을 친 직후 배트가 아래로 처지던 중간 시안도 수정했다.
- **지연된 마무리**: 공을 통과한 뒤 어깨 위로 감기도록 회전을 추가한다. 접촉 직후부터 배트를 세우지 않는다.
- **연속된 속도**: 접촉 전후의 위치와 각속도가 이어진다. 배트 길이는 고정된다.
- **기존 재생 계약 유지**: 접촉 전 80ms + 접촉 후 120ms. 잔상·페이드 없이 단일 배트를 그린다. 시작과 끝에는 손잡이 끝까지 화면 밖에 둔다.
- 정상·짧게 모드의 투구 시간, HIT/OUT 판정, 배당·정산, reduced-motion 처리, 기존 UI는 이번 스윙 작업에서 바꾸지 않았다.

## Pale maple color correction

The 3D bat uses procedural wood, not the pixels of `poc/assets/images/bat.png`. The previous amber key light, ochre base color and strongly brown grain compounded the yellow cast. The base color is now #cdb79b with a white key light, near-neutral hemisphere lighting and a softer cool rim. Grain darkening is less chromatic (0.62/0.53/0.43 at 0.32 strength). The original image remains unchanged; the rendered material approximates its pale beige wood rather than claiming an exact texture match. Day/night contact-frame screenshots were checked after the change. Swing timing, geometry and dimensions are unchanged.
